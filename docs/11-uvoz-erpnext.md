# 11 – Увоз на шифрарници од ERPNext (Next ERP)

Одобрено 11.11.2026, за фирмата **УПСТРЕАМ ДООЕЛ** (ЕДБ 4015023508550). Извор: бекап од 18.08.2026.

## Што се внесува
| ERPNext | Апликација | Правило |
| --- | --- | --- |
| Customer + Supplier | `partners` (улоги купувач/добавувач) | Спојување по ЕДБ. `MK4030…` → ЕДБ + ДДВ број. Ист ЕДБ кај два различни купувачи = грешка во ERPNext → се внесува само првиот |
| Address (примарна / Billing) | адреса, град, пошт. број, држава | една адреса по партнер (апликацијата нема повеќе адреси) |
| Bank Account (на партнер) | `partner_accounts` (`manual`) | наша сметка или сметка на друг партнер → прескокната |
| Contact поврзан со партнер | `partner_contacts` | контакти само од е-пошта (не се поврзани) **не** се внесуваат |
| Item | `items` | шифра > 30 знаци → 25 знаци + `-XXXX`; Парче→ком, Кутија→кут; без Item Tax → 18 % |
| Item Price „Standard Selling“ (без ДДВ) | `items.unit_price` | без цена → 0 |

**Не се внесува:** набавни цени (нема поле), залиха (треба попис на денот на преминот), излезни фактури, нарачки, е-пошта.
**Изводи:** ERPNext нема банкарски трансакции (`tabBank Transaction` = 0). Изводите се внесуваат од е-банкарство (TXT / MT940, docs/08).

## Правила на увозот (`api/src/tools/import-erpnext.ts`)
- Една трансакција; `--dry-run` прави сè и враќа назад.
- Постоечки партнер (ист ЕДБ; без ЕДБ – ист назив) **не се менува**: се додаваат улоги и се пополнуваат **празни** полиња.
- Постоечки артикл (иста шифра) не се менува.
- Може да се пушти повторно: вториот пат не внесува ништо.

## Постапка
1. Локално (не на серверот): бекапот во MariaDB, па `python3 scripts/erpnext-export.py --db erp --out upstream-erpnext.json`.
   Излезот содржи лични податоци (контакти) → **не во git**; по увозот се брише од серверот.
2. Слика со алатката (`20261111-73c0104`, docs/06) мора да е распоредена.
3. PowerShell:
```
$k="$env:USERPROFILE\.ssh\oracle-efaktura.key"; $s="ubuntu@92.5.149.62"
scp -i $k "<папка>\upstream-erpnext.json" "${s}:upstream-erpnext.json"
ssh -i $k $s "cd /opt/efaktura && sudo docker compose exec -T api node dist/tools/import-erpnext.js - --client 4015023508550 --dry-run < ~/upstream-erpnext.json"
ssh -i $k $s "sudo bash /opt/efaktura/bin/04-backup.sh && cd /opt/efaktura && sudo docker compose exec -T api node dist/tools/import-erpnext.js - --client 4015023508550 < ~/upstream-erpnext.json; rm ~/upstream-erpnext.json"
```

## Влезни фактури, плаќања и прилози (одобрено 11.11.2026)
Алатка `api/src/tools/import-erpnext-docs.ts`, извоз `scripts/erpnext-export.py --purchases … --files-from … --files-prefix …`.

| ERPNext | Апликација | Правило |
| --- | --- | --- |
| Purchase Invoice (поднесени; сторнираните не) | `purchase_invoices`, `source = erpnext`, ознака **ERP** | **Прокнижени без залиха** (залихата е од попис), по ред на датум на прием → `UPSTRI-VF-2025-00001…`. Збировите се од ERPNext (`fixed_amounts`) |
| Ставки | `purchase_lines` | ДДВ по ставка од `item_wise_tax_detail`; без ДДВ ред и без ДДВ → `NP` (7 ставки, одобрено); артикл по шифра. Негативни ставки (кредит од курир, 2 фактури: ACC-PINV-2025-00055-1, -00114-1) → збирна ставка по стапка; **забелешка „ЗА ПРОВЕРКА“** со оригиналните ставки |
| Payment Entry (Pay) | **не се внесува** (одлука 11.11) | сите 153 фактури се отворени; ги затвораат изводите за 2025/2026 (увоз од е-банкарство, автоматско поврзување). Алатката ги поддржува (извоз без `--no-payments`) |
| Прилози (PDF/JPG) | **засега не** (одлука 11.11) | алатката ги поддржува: 100 прилози ≈ 70 MB во 5 датотеки по ~15 MB |

- Влезните фактури **никогаш** не одат кон УЈП; „прокнижена“ = проверена.
- Повторен увоз ги прескокнува веќе внесените (ERPNext број), рачно внесена иста фактура (добавувач + број) и истите прилози (SHA-256).
- 2023/2024: ги нема во ERPNext (прва фактура 29.01.2025). Може подоцна од друг извор во ист формат (`erpnext-purchases/1`).
- Проба (празна база, 11.11): 153 фактури (2025: 140 = 1.052.507,83; 2026: 13 = 63.564,53), без плаќања → отворено 1.116.072,36 (сите).
Скрипта за Windows: `scripts/Import-ErpPurchases.ps1` (распоредување → проба → потврда → бекап → увоз → бришење од серверот).

## Излезни фактури (одобрено 11.11.2026)
| ERPNext | Апликација | Правило |
| --- | --- | --- |
| Sales Invoice, поднесени (103, 03.06–28.10.2025, 535.408,68 ден.) | `invoices`, **издадени**, `source = erpnext`, ознака **ERP** | **Бројот од ERPNext** (`ACC-SINV-2025-00007`) – тоа е правниот број на издадениот документ; реден број = бројот од ERPNext; бројачот за 2025 се поставува на најголемиот (119) |
| Сторнирани во ERPNext (13) | не се внесуваат | наведени во извештајот |
| Ставки | `invoice_lines` | попуст како во ERPNext ако дава ист износ; цена со вклучен ДДВ → нето цена = нето износ / количина; ДДВ по ставка |
| Износи | од ERPNext | ACC-SINV-2025-00076: пресметано 3.250,02, ERPNext 3.250,01 → се чува ERPNext |
| Залиха, плаќања, прилози | **не** | плаќањата ги затвораат изводите (како кај влезните) |

- **Не се праќаат кон УЈП:** `invoices.source = 'erpnext'` (миграција 0016); редицата за праќање (`invoices_ujp_pending_ix`) е само за `source = 'app'`. **Агентот мора да праќа само `source = 'app'`.**
- Издадена фактура не се брише (тригер): погрешен увоз се поправа само со сторно → затоа проба + бекап пред увоз.
- Скрипта: `scripts/Import-Erp.ps1 -Email … -File upstream-sales.json [-Deploy <слика>]` (генеричка, и за влезни).

## За проверка од сметководител
