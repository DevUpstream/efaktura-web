# 08 – Плаќања, наплата и изводи од банка (05.11.2026)

Модул `payments` („Плаќања и наплата“), се вклучува по фирма. Слика `20261105-d5e43d7` (ја содржи и `6e77941`). 114 автоматски теста.

## Плаќања и наплата

| Дел | Каде |
| --- | --- |
| **Наплата:** отворени излезни фактури по купувач, по доспевање (не е доспеано, 1–30, 31–60, 61–90, над 90 дена), детали по фактура | Плаќања и наплата → Наплата |
| **Обврски:** отворени прокнижени влезни фактури по добавувач | → Обврски |
| **Уплата / плаќање:** распоред автоматски од најстариот документ или рачно; преплата останува нераспоредена | „Нова уплата“, „Уплата“ кај купувачот |
| **Сторно на уплата** – фактурите повторно се отвораат | → Уплати |
| Салдо на купувачот | Картичка на купувач |

Правила: отворено = „За плаќање“ − книжни одобренија − распоредени уплати; сторнирани и заменети фактури не се долг; уплата не се менува и не се брише (тригер); истовремени внесови за иста фирма се редоследуваат.

## Изводи од банка

### Формати (проверени на вистински изводи)

**Халкбанк и Шпаркасе** даваат ист TXT формат со фиксна ширина (UTF-8, CRLF):

| Ред / колона (знаци) | Содржина |
| --- | --- |
| ред 1 | број на извод |
| ред 2 | датум (dd.MM.yyyy) |
| ред 3 | наша сметка (XXX-XXXXXXXXXX-XX) |
| ред 4 / 5 | претходна / нова состојба (`1,234.56`) |
| 0–70 | назив на налогодавач / примач |
| 70–88 | негова жиро-сметка |
| 88–107 | износ со знак (− = одлив) |
| 107–113 | шифра на плаќање |
| 113–185 | цел на дознака |
| 185–209 | повикување на број (задолжување) |
| 209–233 | повикување на број (одобрување) |
| 233–257 | ЕДБ (само Шпаркасе). **Кај ПП50 кон Трезор тоа е нашиот ЕДБ** – никогаш не се препознава како партнер |
| 257–281 | непознато поле (се чува) |

**НЛБ Банка** (BIC TUTNMK22, сметки 210-…) дава **SWIFT MT940** (UTF-8, CRLF), проверено на вистински извод 09.10.2026 (11.11.2026):

| Таг | Содржина |
| --- | --- |
| `:25:` | наша сметка, 15 цифри → XXX-XXXXXXXXXX-XX |
| `:28C:` | број на извод |
| `:60F:` / `:62F:` | претходна / нова состојба: C/D + YYMMDD + MKD + износ (`130212,00`); датумот од `:62F:` = датум на изводот |
| `:61:` | YYMMDD + MMDD + C/D/RC/RD + износ + `NMSC` + **сметка на другата страна** + `//` + **повикување на број** |
| `:86:` | `/BENM/` (примач, одлив) или `/ORDP/` (налогодавач, прилив) сметка, `/BNAME/` назив, `/PRPD/` цел, `/CODE/` шифра на плаќање. Редовите се прекинати на 65 знаци **среде збор** → се спојуваат без празно место |

Нема ЕДБ во MT940 → препознавање само по сметка, назив и број на фактура. Девизни MT940 и повеќе изводи во една датотека се одбиваат (засега).

**Стопанска банка** (сметки 200-…): **само TXT** (одлука 12.11.2026). Проверено на 13 вистински изводи (08/2026 и 11/2026). MT940, XML, XLS и DAT од Стопанска не се користат: MT940 нема посебно поле за назив и повикување, а DAT има расипана кирилица.

| Дел | Содржина |
| --- | --- |
| ред 1 | `1` + наша сметка (15 цифри) + датум dd.MM.yyyy + број на извод + број на ставки (6) + прилив (14) + одлив (14) + **претходна** состојба (18). Нова = претходна + прилив − одлив |
| ставка 0–5 | `2x y ` (вид; значењето не е познато, не се користи) |
| 5–19 / 19–33 | прилив / одлив (едното е 0) |
| 33–48 | сметка на партнерот (15 цифри) |
| 48–156 | назив |
| 156– | шифра (3 цифри до 2026, потоа 4 букви, на пр. `GDDS`) + повикување задолжува + повикување одобрува (по 24 знаци; кај 4 букви по 35) |
| последни 110 | цел (70) + датум (10) + референца на банката (30) |

Нема ЕДБ на партнерот (во XML/XLS/DAT има само наш ЕДБ) → препознавање по сметка, број на фактура и назив. Проверка: број на ставки, прилив и одлив од заглавјето = збирот од ставките.

**Комерцијална:** форматот не е проверен. Ако даваат MT940 со истите тагови, работи; ако не, увозот одбива со јасна порака (не погодува) и треба примерок. CSV од која било банка работи со мапирање на колоните (се памти по фирма).

| Банка | Формат | Статус |
| --- | --- | --- |
| Халкбанк | TXT фиксна ширина | проверено |
| Шпаркасе | TXT фиксна ширина | проверено |
| НЛБ | MT940 | проверено |
| Стопанска | TXT (свој формат) | проверено (12.11.2026) |
| Комерцијална, други | MT940 или CSV (мапирање) | не е проверено со вистински извод |

### Проверки при увоз
1. **Претходна состојба + промет = нова состојба**, инаку изводот не е целосен или не е точно прочитан → одбиено.
2. **Сметката од изводот мора да е на фирмата** (IBAN / жиро-сметки од „Поставки и PDF“); иста сметка не може да има изводи кај две фирми.
3. **Ист извод не се увезува двапати** (ист документ или иста сметка + број + датум); ист ред не се книжи двапати.
4. **Редослед по датум, не по време на увоз** (12.11.2026, слика `20261112-db07390`). Повеќе датотеки: прво се читаат сите (`POST …/bank-statements/peek`, без запис), па се увезуваат по датум, па по број на изводот. Листата е по датум, па по број.
5. **Континуитет по сметка:** нова состојба на претходниот извод (по датум) = претходна состојба на овој. Ако не е → предупредување „Недостасува извод помеѓу бр. X од Д и …“ и ознака „недостасува извод пред овој“ во листата. Не се одбива: изводот може да дојде подоцна.
6. **Постар извод увезен подоцна** си го зазема местото по датум (ознаката за празнина исчезнува). Предупредување: автоматското поврзување ги гледа фактурите отворени **во моментот на увозот**, па ставките „за обработка“ треба да се проверат.

### Препознавање (автоматско поврзување со фактури)

**Партнер**, по сигурност:

| # | Правило | Сигурност |
| --- | --- | --- |
| 1 | ЕДБ во колоната на изводот | сигурно |
| 2 | Жиро-сметка (рачно внесена или **научена** при претходно книжење) | сигурно |
| 3 | Цел број на наша фактура во целта/повикувањето (`MC-2026-4` = `MC-2026-00004`) | сигурно |
| 4 | ЕДБ (13 цифри) во текстот на целта | предлог |
| 5 | Назив (без ДООЕЛ/ДОО/АД, латиница = кирилица), само ако е единствен | предлог |

**Фактури**, кога партнерот е познат:

| # | Правило | Сигурност |
| --- | --- | --- |
| a | Цел број на фактура | сигурно |
| b | Број/година (`4/2026`, `2026-4`) кај фактурите на тој партнер | сигурно |
| c | Точен износ на една отворена фактура | сигурно |
| d | **Единствена комбинација** на отворени фактури со точен збир (до 16 фактури) | сигурно |
| e | Број на фактурата на добавувачот во целта (за плаќања, на пр. ЕСМ `25-1200-230`) | сигурно |
| f | Инаку од најстарата | предлог |

**Сигурно = партнер по 1–3 И фактури по a–e.** Само сигурните се книжат автоматски (може да се исклучи). Предлозите и непознатите чекаат: „Прокнижи“ (со избор на партнер, автоматски или рачно по фактура) или „Не се книжи“ (провизии, плати, Трезор). Рачното книжење ја **учи жиро-сметката** – следниот извод од истиот купувач е сигурен.

Совети за повеќе автоматика:
- Внесете ги ЕДБ-ата на купувачите (од регистарот на УЈП).
- На PDF-от на секоја издадена фактура што се плаќа стои **„При плаќање, во „повикување на број“ наведете: MC-2026-00004“** (слика `20261105-f56d69c`; се исклучува во „Поставки и PDF“). Не се печати на нацрт, сторно, книжно одобрение и платена фактура.

## Трошоци и преноси од изводи (05.11.2026, слика `20261105-268e817`)

Ставка што не е уплата/плаќање по фактура добива **вид** (не се прави партнер „банка“ – провизијата не е фактура и би останала како погрешно нераспоредено плаќање):

| Вид | Трошок | Автоматски |
| --- | --- | --- |
| Банкарска провизија | да | **да** – одлив со „провизи…“ во целта (`[AutoProv]…Провизија`, `[TRG:ANP]Банкарска провизија`) |
| Јавни давачки (Трезор) | да | **да** – одлив на сметка 100-… |
| Пренос меѓу сопствени сметки | **не** (ни приход ни трошок) | **да** – сметката на другата страна е меѓу сметките на фирмата (IBAN + жиро-сметки во „Поставки и PDF“) |
| Плаќање со картичка | да | предлог (Виза/Мастер/картичка во целта) |
| Плати и дневници | да | предлог (дневници/плата/надомест во целта) |
| Друг трошок | да | рачно |
| Позајмица (основач / поврзано лице) | **не** | рачно |
| Не се книжи | не | рачно |

Таб **„Трошоци“**: збир по месец и вид, посебно „не се ни приход ни трошок“, ставки по вид, CSV (Excel) за сметководителот. Видот се менува или враќа („Врати“) во изводот.

## Платежна дисциплина на купувачот (05.11.2026, слика `20261105-aa751a1`)

Од **нашите** фактури и уплати (без надворешни извори), модул Плаќања:

| Показател | Како |
| --- | --- |
| Просечно задоцнување | денови од рокот до уплатата, пондерирано со износот, уплати во последните 12 месеци |
| % доцна | дел од платеното со задоцнување над 5 дена |
| Задоцнето сега | отворено по рокот + најстар долг (денови) |
| Тренд | последни 90 дена наспроти претходно (±5 дена) |
| **Оценка** | **А** ≤ 5 дена и ништо над 30 · **Б** ≤ 20 и ништо над 60 · **В** ≤ 45 и ништо над 90 · **Г** друго · – без историја |
| **Кредитен лимит** | по купувач (картичка → „Салдо и плаќање“); отворено + нова фактура > лимит → предупредување |

- Листа „Купувачи“: колона „Плаќа“ (А/Б/В/Г).
- Нова фактура: **предупредување** (задоцнет долг над 30 дена, надминат лимит, оценка Г) – не забранува издавање.
- **„Провери во CompanyWall“** на картичката (од 07.11.2026, слика `20261107-62f2320`): директна врска по ЕДБ `companywall.com.mk/prebaruvanje?n=<ЕДБ>`. Бизнис мрежа е отстранета (немаше врска по ЕДБ).

- Постар извод: ставките сè уште се поврзуваат со фактурите отворени денес. За 10: при увоз на постар извод, автоматски да се книжи само по број на фактура (не по „точен износ“/fifo).
