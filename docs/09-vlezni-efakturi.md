Слика `20261106-18ae658`. Модул „Влезни фактури“. 125 автоматски теста.

## Одлука

| Пат | Состојба | Оценка |
| --- | --- | --- |
| **А) Увоз на JSON** што го праќа добавувачот (формат на УЈП е-Фактура) + PDF | **направено** | 7/10 – зависи од добавувачот |

## Првиот примерок (Даталаб → МЦМС, 26-307-006229)

- JSON-от е **payload во формат на УЈП, тип 100** (`{requestTimestamp, document}`), без потпис и без EUID. PDF-от е од нивниот софтвер (Pantheon), без QR. Значи **не е потврдена фактура од УЈП**, туку нивниот извоз.
- Кодот на држава е **„МК“ на кирилица** (`sellerCCode`) – се претвора во `MK`.
- **ДДВ е заокружен на цел денар по ставка** (ставка 2: 27,00 по единица, 54,00 наместо 53,64; вкупно 10.559,00 наместо 10.558,64 по нашата пресметка).

## Правила

| Што | Како |
| --- | --- |
| Влез | Чист JSON, обвивка `{requestTimestamp, jws}` или потпишан JWS (се чита payload; потписот засега не се проверува) |
| Фирма | ЕДБ на купувачот (`buyerTin`) **мора** да е избраната фирма; инаку: „Купувач на фактурата е X (ЕДБ …), изберете ја таа фирма“ |
| Добавувач | По ЕДБ на продавачот; ако го нема, се креира (назив, ЕДБ, ДДВ број, адреса, град, е-пошта). Исклучен добавувач → одбиено. Продавач = купувач → „излезна, не влезна“ |
| **Износи** | **Од документот** (законски документ), за ставки и збир; `fixed_amounts = true`. Разлика со нашата пресметка → **предупредување**, не грешка. Ставки ≠ збир (над 0,05) → одбиено како неусогласен документ |
| За плаќање | `docFinalAmount` (по аванс) → `payable_amount`; наплатата/обврските го користат тој износ, па уплатата од изводот се спарува точно |
| Рок | `docPaymentTypeDueDate`, или датум + `docPaymentTypeDueDays` |
| Ставки | ДДВ стапка по процент (кај 0% и даночен индикатор → по `ujp_code`); попуст = (оригинална − цена) / оригинална |
| Артикли | **Се учат при книжење**: добавувач + опис → артикл (`supplier_item_map`). Следен увоз од истиот добавувач ги поврзува сам |
| Измена на увезена | Само: артикл, зависен трошок, лот, рок на траење, датум на прием, рок за плаќање, магацин, забелешка. Добавувач, број, датум, количини, цени, ДДВ → не (се бара корекција од добавувачот) |
| Дупликат | Ист добавувач + број (несторнирана) → 409 |
| Засега одбиено (со порака) | тип ≠ 100 (книжно одобрение 110 итн.), девизна валута, количина ≤ 0 |
| Чување | Оригиналниот документ (`source_json`) и SHA-256 (`source_hash`) |

## Прилози

- PDF/JPG/PNG до 8 MB, кон секоја влезна фактура (и рачна). Се проверува содржината (`%PDF-`, JPEG, PNG), не наставката.
- При увоз: ако има еден JSON и еден PDF – одат заедно; при повеќе – по ист број (≥ 6 цифри) во имињата или по бројот на фактурата.
- Прилог на прокнижена фактура **не се брише** (тригер во базата); може да се додаде.
- Чување во базата (bytea). При многу фактури → посебно складиште (S3/диск) и бекап.
